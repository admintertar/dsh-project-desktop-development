# 多项目窗口共享 DeepSeek 账号实施计划

**目标：** 同一壳应用登录一次即可在所有项目窗口使用 DeepSeek 账号，退出登录同步生效。

**架构：** Shell 持有应用级账号凭据位置；各 Host 通过最小凭据路由适配复用固定官方 `LocalCredentialProvider` 的读取、原子写入、跨进程锁及监听。只共享 `deepseek-account-platform/default` 与 `device`，项目的 API Key、其他授权、Host 浏览器认证密钥仍留在各自 DSH Home。

**技术：** Electron、Node.js、固定官方 0.2.0-rc.2 credentials/account 服务。

## 已核对的方案

- 共用整个 DSH Home 会连带共享会话、配置与工作区，不适合当前多项目结构。
- 共用整个 credentials 文件还会共享 `client-connection/browser-session` 访问密钥，不能作为账号共享实现。
- 选用账号记录路由：登录弹窗、PKCE、回调、账号信息及撤销授权继续由官方执行；Shell 拥有共享范围和应用生命周期。

## 实施步骤

1. 在 Shell 独立 worktree 中增加官方凭据适配：完整保留官方 provider 接口与引用凭据行为，只将两条账号记录路由到应用 userData 内的共享文件。验证双 Host 登录/删除热同步、关闭重开、API Key 与 Host 密钥隔离。
2. 增加一次性迁移：只读取带官方 Shell 所有权标记的旧项目目录；单一已有登录可接入共享存储，多个不同登录明确报冲突。共享文件一旦初始化就作为权威，退出后不能从旧项目记录恢复。不得输出凭据或重写运行中的 Profile。
3. 在启动项目 Host 前接入账号存储及自有 provider 组合，保持官方源文件与构建产物只读。检查跨窗口退出时的运行任务提示、取消及清理行为。
4. 运行 Shell `yarn run check`、实际双窗口原生验收和必要生命周期回归；用临时账号夹具验证退出，用户现有账号只验证迁移与共享登录状态。
5. 精确集成并本地中文提交，更新此任务的结论与证据；不推送、不发布。

## 验收

- A 登录后 B 自动显示同一账号，新打开的 C 与重启后的窗口也已登录。
- 退出登录后其他窗口更新；保留官方确认与取消，覆盖在途登录和账号任务。
- 旧项目凭据不会在重开时恢复已退出的共享账号。
- 项目会话、API Key、Host 认证与 Chromium 分区保持原有隔离。
- 仅记录脱敏结论与临时项目截图，不把 userData、Cookie 或 token 写入任务资料。
